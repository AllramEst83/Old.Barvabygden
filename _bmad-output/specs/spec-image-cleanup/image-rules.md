# Image Rules (proposed defaults, confirm before use)

## Naming (CAP-1)

- Pattern: `^[a-z0-9]+(-[a-z0-9]+)*\.(webp|jpg|png|gif|ico)$`.
- Lowercase; spaces and underscores become hyphens; `å`/`ä` become `a`, `ö` becomes `o`; extension lowercased (`.jpeg` becomes `.jpg`, `.GIF` becomes `.gif`); strip noise such as `.jpg-for-web-NORMAL`.
- Names stay unique per folder. On collision append a numeric suffix (`-2`) or the topic. Never rename a file twice in one phase.
- Applies to `assets/images/**` and `barva-bladet/**/images/**`.

## Format and size (CAP-3, CAP-4)

| Type | Policy |
|---|---|
| JPG/JPEG photo | `.webp` (quality about 80) plus resized JPG fallback |
| PNG photo (no transparency) | `.webp` plus JPG fallback (new name, old PNG URL redirected) |
| PNG with transparency, logos, line art | lossless `.webp` plus optimized PNG fallback |
| GIF (static) | unchanged |
| `.ico`, existing `.webp` under the caps | unchanged |

Markup for every converted image:

```html
<picture>
  <source type="image/webp" srcset="../assets/images/museum/fence-1.webp">
  <img src="../assets/images/museum/fence-1.jpg" alt="..." width="..." height="...">
</picture>
```

Existing `<img>` attributes (alt, class, size, style) stay on the inner `<img>`. Old browsers without `<picture>` support still render the inner `<img>`.

- Long edge at most 1920 px; images already smaller are never upscaled. Caps apply to the fallback files too.
- Target: typical file under 300 KB, no file over 500 KB; if quality suffers, raise the cap for that file and record why in the manifest.
- Resize and recompress only; no crop, retouch or colour edits. EXIF stripped.

## Duplicates (CAP-2)

- Identical means equal SHA-256. Keep the file in the most specific topic folder that a page references, or in `shared/` when several topics use it; repoint every reference; remove the others with `git rm`.
- Archive per-issue copies are not merged (Constraints in SPEC.md).

## Image manifest (CAP-5)

`scripts/image-manifest.csv`, columns `old_path,new_path,action,old_bytes,new_bytes`; `action` is one of `rename`, `merge`, `resize`, `convert`, `quarantine`, `keep`. A `convert` row records the fallback; the `.webp` sibling is implied by the fallback path. Built and reviewed before any file is touched; later steps read it and nothing hard-codes paths. Rewrites reuse the `scripts/rewrite-links.ps1` approach.

## Unreferenced images (CAP-8)

Before moving, re-scan with a stronger check than a file-name search: `index.html` inline scripts, `fragments/`, `pages/`, `barva-bladet/`, CSS and JS, in decoded and encoded forms. Confirmed files go to `attic/unreferenced-images/<original path>` with `git mv` and a `quarantine` row; add them to `attic/README.md`.

## Redirects and deploy (CAP-6)

- Every `rename`, `merge` and format-changing `convert` row yields `Redirect 301 "/old" "/new"`, generated by `scripts/build-redirects.ps1` into a second marker block (`# BEGIN image redirects` to `# END image redirects`) from the image manifest. `quarantine` rows get none.
- No server delete list: the WinSCP synchronize with "Delete files" on removes server copies that no longer exist in the repo. `scripts/check-live.ps1` checks each image redirect (301 then 200).
- Tool: `scripts/optimize-images.ps1` calls `sharp` through `npx` with a pinned version; it reads the manifest, writes the `.webp` and fallback files, and reports sizes. Re-running changes nothing.

## Verification

- `scripts/check-links.ps1` at or under baseline after every phase.
- A hash scan, a name-pattern scan and a size scan over live images, all with zero hits.
- Visual spot check: `index.html`, one page per topic, three archive issues, both fragments.
- After upload: `scripts/check-live.ps1`, and the home page plus one page per topic by eye.
